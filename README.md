# Автозаполнение статистического бюллетеня

Программа берёт данные из Excel-выгрузок и раскладывает их по ячейкам
Word-шаблона бюллетеня.

| Кому | Что читать |
|---|---|
| Экономисту, который готовит бюллетень | [КАК_ЗАПУСТИТЬ.md](КАК_ЗАПУСТИТЬ.md) — одна страница; после прогона — `output/ЧТО_ПРОВЕРИТЬ.xlsx` |
| Если что-то не заполнилось | [ИНСТРУКЦИЯ_ЕСЛИ_ПОКАЗАТЕЛЬ_НЕ_ЗАПОЛНИЛСЯ.md](ИНСТРУКЦИЯ_ЕСЛИ_ПОКАЗАТЕЛЬ_НЕ_ЗАПОЛНИЛСЯ.md) — «Частые случаи» с реальными примерами |
| Подробно, включая правила сопоставления названий | [ИНСТРУКЦИЯ_ПО_РАБОТЕ_С_АВТОМАТИЗАЦИЕЙ_БЮЛЛЕТЕНЯ.md](ИНСТРУКЦИЯ_ПО_РАБОТЕ_С_АВТОМАТИЗАЦИЕЙ_БЮЛЛЕТЕНЯ.md), блок 2а |
| Другому региону | [REGION_ADAPTATION_GUIDE.md](REGION_ADAPTATION_GUIDE.md) |
Этот файл — про другое: **при каких условиях автозаполнение сработает, при
каких сработает частично, а при каких не сработает вообще.**

---

## 1. Когда сработает полностью

Всё перечисленное должно выполняться одновременно.

| Условие | Почему это важно |
|---|---|
| Коды ОКВЭД / МО стоят в **левом столбце** Excel, по одному на строку | Программа сопоставляет строки бюллетеня со строками Excel по коду. Если коды окажутся в шапке, а показатели — в строках, сопоставлять будет нечем |
| В шапке Excel есть строка, **различающая годы** | Из неё берутся ключевые слова, по которым столбцы двух лет разводятся между собой |
| Названия строк в бюллетене есть в справочниках `okved_mapping.csv` / `mo.csv` | Иначе строку не с чем связать |
| Имена Excel-файлов совпадают с указанными в `table_source_data_mapping.csv` | По ним программа понимает, из какого файла брать данные для каждой таблицы |
| Названия таблиц в Word совпадают с `table_source_data_mapping.csv` | Допускаются опечатки в одну букву, но не переписанные заголовки |

## 2. Что можно менять безопасно

Эти изменения программа переживёт — они покрыты тестами:

- **Вставить или удалить столбец** в Excel. Номера столбцов из маппинга
  устареют, но столбец будет найден заново по ключевому слову. В консоли
  появится `🔄 Структура Excel сдвинулась` — это не ошибка, а сообщение,
  что программа сама пересчитала номер.
- **Дописать строки над шапкой** (пояснения, названия, пустые строки).
  Глубина шапки определяется динамически.
- **Переименовать группу показателей** в шапке — годы всё равно разойдутся,
  потому что различающее слово берётся из строки периода.
- **Заменить «на конец предыдущего/отчетного года» на сами годы** («2023» /
  «2024») или на даты («на 31.12.2023»). Конкретные слова нигде не зашиты.
- **Пересохранить справочники из Excel** — кодировка Windows-1251
  распознаётся наравне с UTF-8.
- **Переименовать Excel-файлы** — при условии, что имена обновлены в
  `table_source_data_mapping.csv`. Признак файла (ОПФ, форма собственности)
  определяется по содержимому, а не по имени.
- **Числа с разделителями тысяч и запятой** — пробелы, включая неразрывные,
  убираются, запятая как десятичный разделитель понимается.

## 3. Что сработает частично

Программа доделает, что сможет, и **скажет, чего не смогла** — всё
собрано в `output/ЧТО_ПРОВЕРИТЬ.xlsx`, а пустые по нашей вине ячейки
подсвечены в `output/Бюллетень_ПРОВЕРКА.docx`. Технические отчёты ниже —
для разработчика.

| Ситуация | Что произойдёт | Где увидите |
|---|---|---|
| Нет данных за один из годов | В ячейке прочерк `-` | `unfilled_tags.xlsx` |
| Название строки не найдено в справочнике | Строка не заполняется, числовые ячейки очищаются | `ЧТО_ПРОВЕРИТЬ.xlsx`, листы 2 и 3 (с ближайшим названием из справочника) |
| Показатель в Word подписан не так, как в Excel | Колонка остаётся пустой (если не сработало ни одно правило сопоставления) | `ЧТО_ПРОВЕРИТЬ.xlsx`, лист 2 |
| Ошибка в списке таблиц (нет файла, название не как в Word) | Таблица не заполняется: числа прошлого периода стираются, ячейки пустые | `ЧТО_ПРОВЕРИТЬ.xlsx`, лист 1 — с подсказкой, как правильно |
| Столбец не подтверждён ключевым словом | Берётся номер из маппинга + предупреждение | Консоль: `⚠️ Не удалось подтвердить столбец` |
| Два столбца одного показателя ничем не различаются в шапке | Годы не разводятся + предупреждение | Консоль: `годы развести не удалось` |
| Один Excel-файл битый или отсутствует | Пропускается только он, остальные обрабатываются | `ошибки_загрузки_excel.txt` |
| Год в шапке продублирован (опечатка) | Заполняется, но помечается | `повторяющиеся_года_в_шапке.xlsx` |
| Название почти совпало со справочником | Заполняется, но требует проверки | `нужна_проверка.xlsx`, `опечатки_в_одну_букву.xlsx` |
| В столбце «количество … единиц» дробное значение | Заполняется как есть, но помечается | `подозрительные_значения.xlsx` |

**Прочерк `-` в готовом документе всегда означает «данных не нашлось».**
Программа не подставляет вместо них ни соседний год, ни соседний столбец —
это принципиально: лучше видимый пропуск, чем правдоподобная неверная цифра.

## 4. Когда не сработает вообще

| Ситуация | Почему |
|---|---|
| Коды ОКВЭД / МО стоят **в шапке**, а не в левом столбце | Перевернутая структура — программа рассчитана на «строка = объект, столбец = показатель» |
| В Excel нет строки, различающей годы | Невозможно определить, какой столбец за какой год |
| Все Excel-файлы битые или папка `input/excel` пуста | Брать данные неоткуда |
| Нет справочников `okved_mapping.csv` / `table_source_data_mapping.csv` | Не с чем сопоставлять |
| Word-шаблон не содержит нужных таблиц | Заполнять нечего |

## 5. Чего программа не делает

Она **почти не проверяет данные на осмысленность**. Единственная такая
проверка — показатели, считающие штуки: если в столбце «количество … единиц»
стоит дробное значение, оно попадёт в бюллетень как есть, но строка окажется
в отчёте `подозрительные_значения.xlsx`. Именно так и был найден реальный
дефект — «количество организаций = 2,3» в `t25OpfVed14.xlsx`.

Всё остальное — проценты вне разумного диапазона, отрицательные суммы,
несходящиеся итоги — программа не контролирует. Смысловой контроль остаётся
за человеком.

Она **не исправляет ошибки исходного бюллетеня**. Наоборот: сверка готового
документа с заполненным вручную оригиналом показала, что ошибки были как раз
в ручном варианте — в одной таблице данные съехали на целый раздел ОКВЭД,
потому что в Word-шаблоне не было строки для раздела J, а заполнявший шёл по
Excel сверху вниз. Программа сопоставляет по коду, а не по порядку строк,
поэтому такой ошибки не делает.

## 6. Как устроен маппинг столбцов

`input/mappings/column_mapping_v2.csv` собирается **один раз** и дальше
используется как есть. На каждом запуске он не пересобирается.

| Состояние файла | Что делает программа |
|---|---|
| Файла нет | Генерирует из Excel (так стартует новый регион) |
| Файл есть и читается | Использует как есть |
| Файл есть, но части источников не хватает | Только предупреждение, файл не трогает |
| Файл повреждён | Не затирает: либо оставляет как есть, либо сохраняет копию `.backup` |

Названия, которые в Word и в Excel написаны по-разному, **в маппинге править не нужно**:
те же слова в другой форме («Уровень рентабельности» — «Рентабельность») программа
узнаёт по основам слов, а совсем разные слова записываются парой в
`input/mappings/синонимы.csv` — она общая для всех бюллетеней и не пропадает при
пересоздании маппинга. Проверено: бюллетени №2 и №3 с удалённым маппингом
заполняются ячейка в ячейку так же, как с выверенным.

Файл **правится вручную** и хранится в репозитории — в нём накоплена
выверка, которую генератор сам не выведет. Проверено прогоном «с нуля»
(удалили маппинг и папку `output/`, как у коллеги, распаковавшего архив):

| | Выверенный маппинг | Сгенерированный заново |
|---|---|---|
| Совпало с оригиналом | 19 807 | 19 180 |
| Прочерков «нет данных» | 346 | 977 |
| Неверных значений | 154 | 150 |

То есть перегенерация обходится примерно в **630 ячеек**, и теряются они
**в прочерки, а не в неверные цифры** — отказ безопасный и целиком виден в
`unfilled_tags.xlsx`. Расходится 187 строк маппинга из 271, в основном
названиями и кодами показателей.

Отсюда правило: **новому региону** перегенерация не страшна (иначе стартовать
не с чего), а **работающую установку перегенерировать без нужды не стоит** —
проще потерять выверку, чем потом её восстановить. Если всё же нужно —
делайте на копии проекта и сверяйте результат с оригиналом бюллетеня.

## 6.1. Переход на следующий период

Год берётся из **заголовка внутри Excel** («Баланс организаций за 2025
год»), а не из имени файла. Предыдущий год считается как отчётный минус
один, поэтому файлы можно называть как угодно — `T25`, `T26` и т.д.

Что нужно сделать руками при смене периода:

1. Положить новые Excel-файлы в `input/excel/`.
2. Обновить их имена в `table_source_data_mapping.csv` и
   `column_mapping_v2.csv`. Если забыть — программа скажет, что файл не
   найден, а не возьмёт молча чужой.
3. Убедиться, что подписи годов в шапках бюллетеня переведены на новый
   период. Где подпись осталась от прошлого года, в ячейке будет прочерк —
   программа не подставляет данные соседнего года.

Проверено сквозным прогоном: при переименовании всех файлов в `T25`, сдвиге
отчётного года на 2025 и переводе подписей лет **19 755 значений из ~20 300
совпали** с обычным прогоном; остальные различия — подписи самих годов.

## 7. Проверка после изменений в коде

```
python3 -m pytest tests/ -q      # должны пройти все (сейчас 119)
python3 main.py                  # полный прогон на реальных данных
```

Тесты покрывают именно те дефекты, которые уже случались:

| Файл | Что защищает |
|---|---|
| `test_year_column_separation.py` | Годы не схлопываются в один столбец из-за объединённой шапки |
| `test_keyword_parsing.py` | Название показателя не режется по запятым |
| `test_word_document_integrity.py` | Подписи не затираются, отсутствующий год даёт прочерк, форматирование |
| `test_economist_scenarios.py` | Правки исходных файлов руками |
| `test_column_shift_resilience.py` | Сдвиг столбцов в Excel |
| `test_deep_header_resilience.py` | Глубокая многоуровневая шапка |
| `test_crash_resilience.py` | Битые и отсутствующие файлы |
| `test_csv_encoding_resilience.py` | Справочники в Windows-1251 |
| `test_filename_independence.py` | Определение типа файла по содержимому |
| `test_table_name_fuzzy.py` | Опечатки в названиях таблиц |

Тесты проверяются и в окружении Windows 7 (Python 3.8, pandas 2.0 —
`requirements-win7.txt`). Готовый exe для Windows 7 собирается на GitHub
Actions (`.github/workflows/build-exe-win7.yml`) и перед выкладкой
прогоняет бюллетень из ветки: результат сравнивается с
`output/Бюллетень_ГОТОВЫЙ.docx` ячейка в ячейку.

## 8. Насколько точно заполняется

**Бюллетени №2 и №3** (2025 год, ветки `bulletin-2`, `bulletin-3`):
каждое число, поставленное по тегу, сверено напрямую с ячейкой Excel —
в бюллетене №3 это 12 768 чисел, неверных 0. Пустые ячейки — на листе
«2 Пустые ячейки» `ЧТО_ПРОВЕРИТЬ.xlsx`: таблицы без Excel-файла
(сводные 1–3), строки, которых нет в Excel, и названия, которые
программа не угадывает.

**Бюллетень №1** (2024 год, ветка `main`) — сверка готового документа с
заполненным вручную бюллетенем по всем 140 таблицам:

- совпало **19 807 ячеек из 20 307 (97,5%)**;
- 346 ячеек — прочерки там, где данных в источниках нет;
- 154 расхождения, **все проверены вручную и вызваны дефектами исходных
  данных**, а не программой: сдвиг разделов в ручном оригинале,
  переставленные местами годы, дробное «количество организаций» в Excel.
