# Автозаполнение статистического бюллетеня

Программа берёт данные из Excel-выгрузок и раскладывает их по ячейкам
Word-шаблона бюллетеня.

Пошаговая инструкция для пользователя — в
[ИНСТРУКЦИЯ_ПО_РАБОТЕ_С_АВТОМАТИЗАЦИЕЙ_БЮЛЛЕТЕНЯ.md](ИНСТРУКЦИЯ_ПО_РАБОТЕ_С_АВТОМАТИЗАЦИЕЙ_БЮЛЛЕТЕНЯ.md).
Этот файл — про другое: **при каких условиях автозаполнение сработает, при
каких сработает частично, а при каких не сработает вообще.**

---

## 1. Когда сработает полностью

Всё перечисленное должно выполняться одновременно.

| Условие | Почему это важно |
|---|---|
| Коды ОКВЭД / МО стоят в **левом столбце** Excel, по одному на строку | Программа сопоставляет строки бюллетеня со строками Excel по коду. Если коды окажутся в шапке, а показатели — в строках, сопоставлять будет нечем |
| В шапке Excel есть строка, **различающая годы** | Из неё берутся ключевые слова, по которым столбцы двух лет разводятся между собой |
| Названия строк в бюллетене есть в справочниках `okved_mapping.csv` / `mo.csv` | Иначе строку не с чем связать |
| Имена Excel-файлов совпадают с указанными в `table_source_data_mapping.csv` | По ним программа понимает, из какого файла брать данные для каждой таблицы |
| Названия таблиц в Word совпадают с `table_source_data_mapping.csv` | Допускаются опечатки в одну букву, но не переписанные заголовки |

## 2. Что можно менять безопасно

Эти изменения программа переживёт — они покрыты тестами:

- **Вставить или удалить столбец** в Excel. Номера столбцов из маппинга
  устареют, но столбец будет найден заново по ключевому слову. В консоли
  появится `🔄 Структура Excel сдвинулась` — это не ошибка, а сообщение,
  что программа сама пересчитала номер.
- **Дописать строки над шапкой** (пояснения, названия, пустые строки).
  Глубина шапки определяется динамически.
- **Переименовать группу показателей** в шапке — годы всё равно разойдутся,
  потому что различающее слово берётся из строки периода.
- **Заменить «на конец предыдущего/отчетного года» на сами годы** («2023» /
  «2024») или на даты («на 31.12.2023»). Конкретные слова нигде не зашиты.
- **Пересохранить справочники из Excel** — кодировка Windows-1251
  распознаётся наравне с UTF-8.
- **Переименовать Excel-файлы** — при условии, что имена обновлены в
  `table_source_data_mapping.csv`. Признак файла (ОПФ, форма собственности)
  определяется по содержимому, а не по имени.
- **Числа с разделителями тысяч и запятой** — пробелы, включая неразрывные,
  убираются, запятая как десятичный разделитель понимается.

## 3. Что сработает частично

Программа доделает, что сможет, и **скажет, чего не смогла**. Проверяйте
отчёты в папке `output/`.

| Ситуация | Что произойдёт | Где увидите |
|---|---|---|
| Нет данных за один из годов | В ячейке прочерк `-` | `unfilled_tags.xlsx` |
| Название строки не найдено в справочнике | Строка не заполняется, числовые ячейки очищаются | `mapping_validation_log.txt` |
| Столбец не подтверждён ключевым словом | Берётся номер из маппинга + предупреждение | Консоль: `⚠️ Не удалось подтвердить столбец` |
| Два столбца одного показателя ничем не различаются в шапке | Годы не разводятся + предупреждение | Консоль: `годы развести не удалось` |
| Один Excel-файл битый или отсутствует | Пропускается только он, остальные обрабатываются | `ошибки_загрузки_excel.txt` |
| Год в шапке продублирован (опечатка) | Заполняется, но помечается | `повторяющиеся_года_в_шапке.xlsx` |
| Название почти совпало со справочником | Заполняется, но требует проверки | `нужна_проверка.xlsx`, `опечатки_в_одну_букву.xlsx` |

**Прочерк `-` в готовом документе всегда означает «данных не нашлось».**
Программа не подставляет вместо них ни соседний год, ни соседний столбец —
это принципиально: лучше видимый пропуск, чем правдоподобная неверная цифра.

## 4. Когда не сработает вообще

| Ситуация | Почему |
|---|---|
| Коды ОКВЭД / МО стоят **в шапке**, а не в левом столбце | Перевернутая структура — программа рассчитана на «строка = объект, столбец = показатель» |
| В Excel нет строки, различающей годы | Невозможно определить, какой столбец за какой год |
| Все Excel-файлы битые или папка `input/excel` пуста | Брать данные неоткуда |
| Нет справочников `okved_mapping.csv` / `table_source_data_mapping.csv` | Не с чем сопоставлять |
| Word-шаблон не содержит нужных таблиц | Заполнять нечего |

## 5. Чего программа не делает

Она **не проверяет данные на осмысленность**. Если в Excel написано
«количество организаций = 2.3», в бюллетень попадёт 2,3 — так и было
найдено при сверке (`t25OpfVed14.xlsx`, строка 251). Смысловой контроль
остаётся за человеком.

Она **не исправляет ошибки исходного бюллетеня**. Наоборот: сверка готового
документа с заполненным вручную оригиналом показала, что ошибки были как раз
в ручном варианте — в одной таблице данные съехали на целый раздел ОКВЭД,
потому что в Word-шаблоне не было строки для раздела J, а заполнявший шёл по
Excel сверху вниз. Программа сопоставляет по коду, а не по порядку строк,
поэтому такой ошибки не делает.

## 6. Что нельзя делать с маппингом

`input/mappings/column_mapping_v2.csv` **нельзя просто перегенерировать
заново**, удалив файл. Генератор выдаст другие названия и коды показателей
(проверено: меняются 199 строк из 271), а от этих кодов зависит разметка
Word-шаблона — заполнение развалится.

Если маппинг всё же нужно перестроить, делайте это на копии проекта и
сверяйте результат с оригиналом бюллетеня.

## 7. Проверка после изменений в коде

```
python3 -m pytest tests/ -q      # 49 тестов, должны пройти все
python3 main.py                  # полный прогон на реальных данных
```

Тесты покрывают именно те дефекты, которые уже случались:

| Файл | Что защищает |
|---|---|
| `test_year_column_separation.py` | Годы не схлопываются в один столбец из-за объединённой шапки |
| `test_keyword_parsing.py` | Название показателя не режется по запятым |
| `test_word_document_integrity.py` | Подписи не затираются, отсутствующий год даёт прочерк, форматирование |
| `test_economist_scenarios.py` | Правки исходных файлов руками |
| `test_column_shift_resilience.py` | Сдвиг столбцов в Excel |
| `test_deep_header_resilience.py` | Глубокая многоуровневая шапка |
| `test_crash_resilience.py` | Битые и отсутствующие файлы |
| `test_csv_encoding_resilience.py` | Справочники в Windows-1251 |
| `test_filename_independence.py` | Определение типа файла по содержимому |
| `test_table_name_fuzzy.py` | Опечатки в названиях таблиц |

## 8. Насколько точно заполняется

Последняя сверка готового документа с заполненным вручную бюллетенем по
всем 140 таблицам:

- совпало **19 807 ячеек из 20 307 (97,5%)**;
- 346 ячеек — прочерки там, где данных в источниках нет;
- 154 расхождения, **все проверены вручную и вызваны дефектами исходных
  данных**, а не программой: сдвиг разделов в ручном оригинале,
  переставленные местами годы, дробное «количество организаций» в Excel.
