# План тестирования

Составлен по трём общепринятым основаниям, а не «из головы»:

- **ISO/IEC 25010** — восемь характеристик качества программного продукта
  (функциональная пригодность, производительность, совместимость, удобство,
  надёжность, безопасность, сопровождаемость, переносимость). Стандарт
  применяют в том числе к ETL-процессам — то есть ровно к таким программам,
  как наша: «взять данные из источника, преобразовать, положить в приёмник».
- **Шесть измерений качества данных** — полнота, точность, согласованность,
  валидность, уникальность, своевременность.
- **Техники проектирования тестов** — классы эквивалентности, граничные
  значения, негативные тесты, регрессия.

## 2. Чего НЕ хватает — проверить завтра

### 2.1. Валидность данных (главный пробел)

Программа не проверяет данные на осмысленность. Уже найден реальный случай:
в `t25OpfVed14.xlsx` в столбце «количество организаций» стоит **2.3** —
дробное число организаций. Оно попало в бюллетень как есть.

**Что сделать:** проверить, можно ли по названию столбца понять ожидаемый
тип значения («количество … единиц» → целое, «в % к …» → 0-100 или около,
«темп роста в %» → положительное) и выдавать отчёт о подозрительных
значениях. Не блокировать заполнение — только предупреждать.

### 2.2. Граничные значения

Классика: ошибки скапливаются на границах. Не проверено:

- Excel из одной строки данных / из одного столбца.
- Таблица без единой строки данных.
- Показатель в самом первом и самом последнем столбце файла.
- Очень длинное название показателя (перенос, склейка дефисом).
- Номер столбца в маппинге равен 0, отрицательный, равен числу столбцов.
- Отчётный год на границе диапазона (1999, 2100) и вне его.
- Бюллетень с одной таблицей и бюллетень без таблиц вовсе.

### 2.3. Уникальность

- Два одинаковых кода ОКВЭД в одном Excel — какая строка победит? Поведение
  должно быть предсказуемым и одинаковым от запуска к запуску.
- Два показателя с одинаковым названием в одном файле.
- Одинаковые названия строк в бюллетене в разных таблицах.

### 2.4. Повторяемость и запуск с нуля

- **Идемпотентность:** два запуска подряд должны давать одинаковый результат.
  Второй запуск видит папку `output/` от первого — важно, что это ни на что
  не влияет.
- **Чистый старт:** нет папки `output/`, нет `column_mapping_v2.csv` — как у
  коллеги, который только распаковал архив.
- **Запуск из другой рабочей папки** (двойной клик по `.exe` из проводника).

### 2.5. Производительность

Сейчас прогон занимает заметное время. Замерить и зафиксировать: сколько
занимает полный цикл, не растёт ли время нелинейно при увеличении числа
строк. Нужно, чтобы коллега понимал, сколько ждать, и чтобы мы заметили,
если что-то станет вдвое медленнее.

### 2.6. Удобство (сообщения и отчёты)

Проверить глазами, что по каждому предупреждению понятно, **что делать**:
- «Не удалось подтвердить столбец» — куда смотреть?
- «годы развести не удалось» — что править?
- «название не найдено ни в ОКВЭД, ни в МО» — какой файл открыть?

## 3. Порядок прогона завтра

1. `python3 -m pytest tests/ -q` — все тесты должны пройти.
2. `python3 main.py` на реальных данных — прогон без падений.
3. Сверка готового бюллетеня с оригиналом (скрипт сравнения) — расхождения
   не должны вырасти относительно зафиксированных **154**.
4. Второй запуск подряд — результат должен совпасть с первым.
5. Прогон на копии с удалёнными `output/` и `column_mapping_v2.csv`.
6. Просмотр всех отчётов в `output/` глазами.
7. Сборка `.exe` и запуск из папки, отличной от папки с исходниками.

## 4. Что считать регрессией

| Показатель | Текущее значение | Регрессия, если |

| Тесты | 59 проходят | хоть один упал |
